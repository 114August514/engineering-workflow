# engineering-workflow

一套让 AI 和人一起从 0 搭出工程化项目的工作流。

**设计目标不是"让 AI 写更多代码"，是"让人审得动 AI 写的代码"。**

2026 年的数据：高 AI 采用团队合并 PR 数 +98%、PR 体积 +154%，
但评审时间 +91%、缺陷 +9%。瓶颈已经从"写"移到"审"。所以这套流程的每一个
设计选择，都是在把审计前移到**又小又致命**的产物上——意图、决策、契约、迁移——
而不是后置到一大堆实现代码上。

## 装

```bash
./install.sh
```

把 `skills/engineering-project` 软链进 `~/.claude/skills/`。改仓库即改 skill。

## 用

```bash
# 看有哪些技术栈 adapter
~/.claude/skills/engineering-project/scripts/new-project.sh --list

# 建新项目（骨架语言无关，adapter 只填 stack.mk 里的命令）
~/.claude/skills/engineering-project/scripts/new-project.sh ~/Projects/shop --adapter ts-bun

# 在任意项目里
make check    # 提交前唯一要记的命令
make doctor   # 工程基线还缺什么
make audit    # 待人审清单（增量：这次改动，每个 PR 跑）
make review   # 里程碑复盘（全量：整个仓库，阶段结束时跑）
make journal  # 谁在做什么 / 孤儿锁 / 悬空的仓外副作用
```

Claude 会在你说"帮我起个新项目"、"这个需求怎么拆"、"这个 PR 我该看什么"
之类的时候自动触发这个 skill。

## 七个阶段、六个闸门 + 两种评审

| 阶段 | 产物 | 🚦 人审什么 |
|---|---|---|
| P0 意图 | `docs/spec.md`：问题 / 非目标 / EARS 验收标准 | **G1** 非目标、标准能不能被机器判定 |
| P1 领域 | `docs/glossary.md`：术语 / 边界 / 不变量 / 状态机 | （并入 G1） |
| P2 决策 | `docs/decisions/`：ADR | **G2** ADR——决策不可逆，代码可逆 |
| P3 骨架 | 端到端跑通**且已部署**的最薄链路 + 工程基线 | **G3** 亲手跑 `make dev`，点开线上 URL |
| P4 契约 | `contracts/` + `migrations/` | **G4** schema diff——又小又致命 |
| P5 切片 | 一次一条垂直切片，测试先行 | **G5** 分级审计清单，PR 有尺寸上限 |
| P6 交付 | 发布 / 回滚 / 监控 / 备份 | **G6** "炸了怎么回滚"（演练过才算） |

**不是所有事都走完整流程。** 先分流：微改直接做，功能走单闸门，
只有结构性改动（新项目、动契约、动权限）才走七阶段。
**修 bug 单独一档**——改一个字符也要先有会失败的回归测试。

线性流程之外还有两个评审（`references/review.md`）：

- **缺陷评审**（10 分钟，每次修完 bug）——第一条就是"有没有先红后绿的回归测试"，
  没有就不用往下看
- **里程碑复盘**（30—45 分钟，阶段结束或两周一次）——`make review` 全仓库扫描
  架构侵蚀、术语漂移、skip 的测试、大文件、技术债、依赖膨胀、文档过期，
  人再看 spec 是否还成立、技术债有没有登记、下阶段最大风险。
  **每个 PR 都过了不代表整体还立得住**：侵蚀在每个 PR 里都合规，
  只有拉远了看才看得见。

## 六个设计选择

### 1. 分流，不是所有改动一视同仁

大部分 AI 工作流让每一次改动都走 brainstorm → spec → plan → execute。
代价是仪式感压过实际收益，然后人开始跳过步骤，流程就崩了。
这里按**风险**分四档（微改 / 缺陷修复 / 功能 / 结构），只有最后一档走全流程。

### 2. 工程规范与技术栈解耦

通用的是**标准动词接口**：

```
make setup / dev / fmt / fmt-check / lint / typecheck / test
make check / build / ship / audit / review / journal / doctor
```

语言差异只存在于 `stack.mk` 一个文件（八个变量）。于是：
人和 AI 跨项目零学习成本、`AGENTS.md` 里永远写 `make check`、
CI 和本地跑同一条命令、换技术栈只改一个文件。

写一个新语言的 adapter = 填八个变量。

### 3. 按可逆性决定投入

AI 写额外代码几乎零成本，人审它的成本却一样——所以过度设计和"为不会发生的故障
建防御"消耗的是同一个稀缺资源。规则：**不可逆的（数据、钱、契约、权限）防住；
可逆的、能重试的让它失败，但保证失败可见。** 纯推理出来的风险写进风险表，
不写进代码。

这条同样管住这套流程自己：清单是 checklist 不是待办，没有信号就不要逐条去找；
某个环节持续没发现过真问题就删掉它。

### 4. 先搜后写，抄完必须适配

AI 最常见的重复造轮子不是引错了库，是**在仓库里已经有一个实现的情况下又写一个**——
它不会主动全局搜。所以内环第 0 步是 grep 这个仓库，然后才是标准库、
已装依赖、新依赖。安全、时间与时区、协议解析、金额精度、重试退避
**一律用成熟实现**（判据：边界情况我能列全吗）。

但复用只做一半是负债：抄进来的东西必须换成术语表里的命名、删掉用不到的部分、
接上本项目的错误模型和日志格式。**读起来应该像这个项目里长出来的，
而不是贴上去的。**

### 5. 用操作系统的方式处理多方协作

AI 会话会死——被压缩、被打断、超时。死在半路时仓库处于未知状态，
下一个会话完全不知道刚才在干什么。这是崩溃恢复问题，所以借三个 OS 机制：

- **预写日志**：先写意图再动手。写完意图那一刻是可恢复的，反过来什么都不剩
- **undo log**：`git revert` 撤不掉已跑的迁移、已发的部署、已建的外部资源。
  **产生仓外副作用之前先写下怎么撤销它**——写不出来就是需要人点头的信号
- **锁**：粒度是限界上下文（文件级太细、仓库级太粗）。
  日志里「进行中」的条目就是锁；超过 24 小时没动的是孤儿锁，需要回收

不做任务数据库、不做真锁、不做调度器——git 已经是代码的日志，
这里只补它记不了的三样。

### 6. spec 漂移是机械可查的

SDD 的公认短板是 spec 和代码会悄悄不一致，通常只能靠人定期对一遍。
这里：每条验收标准有 `REQ-ID`，测试名里必须带这个 ID，`make audit` 做双向检查——
**孤儿需求**（spec 里有、测试里没有）和**孤儿测试**（测了 spec 里不存在的东西）
都会被报出来。不依赖任何人的自觉。

## 目录

```
skills/engineering-project/
├── SKILL.md              # 分流 + 阶段路由（每次都会进上下文，所以很短）
├── references/
│   ├── intake.md         # P0 需求澄清：EARS 句式、例子驱动、非目标
│   ├── domain.md         # P1 通用语言、限界上下文、不变量、状态机
│   ├── architecture.md   # P2 ADR、选型收敛、风险排序
│   ├── skeleton.md       # P3 walking skeleton、标准动词、工程基线清单
│   ├── contract.md       # P4 契约先行、错误模型、迁移三步走
│   ├── slices.md         # P5 垂直切片、测试先行、PR 尺寸上限
│   ├── delivery.md       # P6 环境、发布、回滚、监控、备份
│   ├── audit.md          # ★ 审什么：分级清单 + AI 失败模式
│   ├── review.md         # ★ 怎么审：评审协议、反馈三级、收到反馈怎么办、里程碑复盘
│   ├── proportion.md     # ★ 做多少：不过度设计、不追幻影风险、按可逆性决定投入
│   ├── reuse.md          # ★ 别造轮子：四层检索、哪些不许手搓、抄完必须适配
│   ├── journal.md        # ★ 在途/回退/并发：预写日志、undo log、锁粒度
│   ├── bugfix.md         # 缺陷修复：复现→回归测试→根因→找同类→回填
│   ├── handoff.md        # 人机对接：AGENTS.md、任务卡、上下文管理
│   ├── conventions.md    # 标准动词、目录、命名、git
│   ├── backend.md        # 技术专题：分层、事务与并发、数据库、可观测性
│   └── frontend.md       # 技术专题：契约消费、三态、AI 看不见界面怎么验收
└── scripts/
    ├── new-project.sh    # 建项目
    ├── doctor.sh         # 工程基线体检
    ├── audit.sh          # 待人审清单（增量）
    ├── review.sh         # 里程碑复盘（全量）
    └── journal.sh        # 在途工作 / 孤儿锁 / 悬空副作用

templates/
├── project-skeleton/     # 语言无关：Makefile / AGENTS.md / docs / contracts / CI
└── adapters/             # 每个语言一个 .mk（八个变量）+ 一段 CI 运行时片段

tests/                    # 这个仓库自己的回归测试，CI 在 ubuntu + macos 上跑
├── verbs-consistent.sh   # 标准动词三处一致
├── docs-links.sh         # 文档交叉引用没断
└── journal-behaviour.sh  # journal.sh 三项检测真的会触发
```

macOS runner 不是凑数：BSD 工具链专门用来拦 GNU-only 的写法
（`\s` / `stat -c` / `date -d` / `sed -i` / `readlink -f` / `xargs -r`），
这些在 macOS 上要么直接失败，要么**静默降级成错误答案**。

调研笔记在 `docs/research/`。
