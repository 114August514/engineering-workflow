# 里程碑模板

GitHub **没有**原生的 milestone 模板机制——建 milestone 时把下面这段粘进描述框。

一个里程碑 = **一组切片 + 一次复盘**。复盘不是可选项：
每个 PR 都过了，不代表整体还立得住，侵蚀在每个 PR 里都合规。

---

```markdown
## 这个里程碑交付什么

<一句话。必须是**用户可见**的，不是"重构了 service 层"。>

## 覆盖哪些需求

- REQ-XXX-001
- REQ-XXX-002

## 完成判定

<不是"所有 issue 关闭"，是能观察到的现象：>
- [ ] 上述 REQ 全部有先红后绿的测试，`make audit` 无孤儿需求
- [ ] 已部署到生产并可访问
- [ ] `make check` 与 CI 全绿

## 明确不在这个里程碑内

<至少两条。不写的话范围会在最后一周膨胀。>
-
-

## 最大的风险

<对照 docs/decisions/ 里的风险表。排第一的应该最先做，不是最容易的先做。>

---

## 收尾复盘（`make review` + 人看这三条）

跑 `make review` 拿到机器部分（架构侵蚀 / 术语漂移 / skip 的测试 / 大文件 /
技术债 / 依赖膨胀 / 文档过期 / 配置项没人用），然后人回答脚本查不了的三条：

- [ ] **spec 还成立吗** —— 非目标被突破了吗？验收标准和实际行为对得上吗
- [ ] **技术债登记了吗** —— 这段时间口头说过的「以后再说」，写下来了吗
- [ ] **下一阶段最大的风险是什么** —— 重排一次风险表

**复盘至少要产出一条改动。** 全是"没问题"通常意味着看得不够仔细。
```

---

## 里程碑该切多大

判据：**一次复盘能在 30—45 分钟内做完。**

做不完说明里程碑太大了——复盘会退化成走过场，而复盘是唯一能看见
"整体是否还立得住"的机会。

时间上大致对应 1—2 周、5—10 条切片。超了就拆成两个。
